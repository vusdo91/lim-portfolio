## 1. 현재 작업 범위와 방향

- 미술작품 포트폴리오의 Index 진입·탐색 경험을 수정했다.
- 현재 구현 대상은 별도 테스트 페이지 `/index-prototype`이다. 기존 메인 `/` 전체를 교체하거나 실제 서비스에 배포한 것으로 이해하면 안 된다.
- 참고 사이트는 https://experiment.obys.agency/ 이며, 작품 배열과 마우스에 반응하는 탐색 경험을 참고했다. 수치나 움직임을 그대로 복제한 것은 아니다.
- 작품마다 멈춰 연출을 기다리는 방식에서 벗어나 연속적으로 작품을 탐색한다.
- 데스크톱은 마우스 호버와 입체 움직임, 모바일은 중앙 작품 선택과 관성 스와이프를 사용한다.
- Works·About 등 다른 페이지의 기존 기획은 이번 변경 대상이 아니다.

## 2. 여자 실루엣: 탐색 중에는 사라짐, 최초 인트로는 남아 있음

**‘여자 실루엣 제거’는 현재 코드 기준으로 작품 탐색 화면에서 사라지는 것을 뜻한다. 최초 진입 인트로까지 완전히 삭제된 상태는 아니다.**

- 최초 진입 시 여자 실루엣 WebM 인트로를 재생한다.
- 영상의 약 3.5초 지점에서 실루엣 페이드아웃과 작품 콘텐츠 페이드인을 시작한다.
- 현재 실루엣 페이드아웃은 1,000ms, 콘텐츠 페이드인은 700ms이며, 두 시간 중 긴 시간이 지난 뒤 작품 탐색을 활성화한다.
- 작품을 넘길 때마다 실루엣이 다시 걷거나 돌아보는 연출은 없다. 탐색 중에는 실루엣을 표시하지 않는다.
- 인트로 중 입력이 쌓여 탐색 시작 직후 작품이 멀리 이동하지 않도록 한다.
- 최초 인트로까지 완전히 없애는 것은 현재 구현과 다른 추가 변경이다. 이미 완료된 일로 기록하지 않는다.

## 3. 데스크톱 최종 확정 동작

### 작품 나열과 연속 스크롤

- 작품을 가로로 배열한다. 아래로 스크롤하면 작품이 오른쪽에서 왼쪽으로 이동하고, 위로 스크롤하면 반대 방향으로 이동한다.
- 휠·트랙패드 입력량에 따라 연속 이동한다. 한 번 입력할 때 작품 하나만 넘기는 제한은 없다.
- 작품별 입력 잠금이나 중앙 자동 정렬, 스냅을 사용하지 않는다. 진행 중 새 입력과 반대 방향 입력도 받는다.
- 현재 목록 양 끝에서 멈추며, 무한 반복 갤러리는 구현하지 않았다.
- 현재 작품 목록은 원격 작품 데이터를 우선 사용하고, 없으면 로컬 작품 목록으로 대체한다. 초기의 작품 3개 고정 테스트 단계와 다르다.

### 전체 화면 마우스 반응과 XYZ 움직임

- 작품이 있는 영역뿐 아니라 페이지 상단·하단 여백과 헤더를 포함한 전체 페이지에서 마우스 이동에 반응한다.
- 작품은 마우스와 반대 방향으로 X/Y 이동하며 부드럽게 따라온다. 작품별 이동 강도 차이를 유지한다.
- 마우스 이동에 따른 이동량은 이전 대비 50% 늘렸다. 기준값은 X 16→24px, Y 24→36px이다. 실제 이동량에는 작품별 계수가 적용된다.
- Z축 포함안을 비교 후 확정했고, 상단 비교 토글을 제거했다.
- 마우스가 오른쪽 끝으로 가면 작품 열의 오른쪽이 사용자에게 가까워지고 왼쪽은 멀어진다. 왼쪽으로 가면 반대로 동작한다.
- 마우스 상하 이동은 기존의 반대 방향 Y 이동만 적용하며, 위아래로 기울이지 않는다.
- 구현은 작품 각각을 Z축으로 이동시키는 방식이 아니라, 작품 열의 공통 평면을 화면 중앙 기준으로 Y축 회전시키는 방식이다. 이 회전이 좌우의 깊이 차이를 만든다.
- 화면을 벗어나면 마우스 반응을 중립 상태로 되돌린다.

### 이미지 컬러와 확대

- 컬러 비교 테스트의 **1안**으로 확정했다. 비교 토글은 제거했다.
- 호버가 없으면 **전체 작품이 컬러**다.
- 작품 이미지에 호버하면 **그 작품만 컬러를 유지하며 살짝 확대**되고 나머지는 연한 흑백이 된다.
- 호버를 해제하면 전체 컬러로 복귀한다.
- 흑백은 `grayscale(1)`과 `opacity: 0.55`로 처리한다. 밝은 배경과 섞어 진한 흑백보다 연하게 보이도록 했다.
- 컬러·투명도 전환은 `350ms ease`다. 따라서 빠른 호버 교체에서는 이전 작품의 색이 전환 시간 동안 서서히 사라진다.
- 확대는 최종 `scale(1.045)`이고 전환은 200ms다. 원래 확대량 3%를 50% 늘려 4.5%로 만든 것이며, 이미지 전체 크기를 1.5배로 키운다는 뜻은 아니다.
- 확대가 주변 작품의 위치나 간격을 밀어내지 않도록 한다.

### 작품 크기와 간격

- 작품 크기는 수정 전 대비 80%로 줄였다. 슬롯 너비와 이미지 최대 높이에 반영했다.
- 작품 간 간격은 당시 기준보다 20% 늘렸다. 이후 모바일은 별도로 간격을 추가 확대했다.
- 이미지 원본 비율을 유지하고 임의로 잘라 채우지 않는다.

### 제목·년도 표시

- 데스크톱의 ‘가운데 작품 정보 표시’ 기획은 취소했다. **실제 호버한 작품의 정보**를 표시한다.
- 하단에 `제목 / 년도` 형식으로 한 줄 표시한다. 슬래시 앞뒤에 공백을 둔다.
- 글씨는 80px, 굵기 800이다. 테스트 페이지 전체 폰트는 Pretendard Variable로 변경했다.
- 제목·슬래시·년도를 하나의 연속된 문자열로 처리해 한 글자씩 아래에서 올라오며 선명해지게 한다.
- 호버 해제 시 마지막 글자부터 역순으로 내려가며 투명해진다.
- 등장 도중 해제하면 완료 상태로 점프하지 않고 **현재 위치·투명도·진행 시점에서 역재생**한다.
- 퇴장 중 다른 작품에 호버하면 이전 애니메이션을 즉시 취소하고 새 작품의 등장을 시작한다. 같은 작품에 다시 진입해도 새 등장을 시작한다.
- 등장과 퇴장 속도를 모두 초기 타임라인의 1.5배로 맞췄다.
- `y`, `g`처럼 아래로 내려오는 글자가 잘리지 않도록 글자 마스크 하단에 여유를 추가했다.
- 이 정보 영역에는 설명·제작도구·작품 크기 등의 상세 메타데이터를 추가하지 않는다.

### Z축 추가 후 호버 오류 수정

- 기울어진 작품 이미지에 커서가 있어도 기존 호버 효과가 맞지 않는 문제가 있었다.
- 투명한 3D 컨테이너가 이미지의 포인터 판정을 방해하지 않도록 하고 실제 이미지가 입력을 받게 수정했다.
- 마우스 이동뿐 아니라 작품 이동·기울기 갱신 때도 브라우저의 실제 이미지 판정(`elementFromPoint`)으로 호버 대상을 갱신한다.
- 커서가 멈춰 있어도 그 아래 작품이 움직이면 컬러·확대·제목이 같은 작품을 가리키도록 상태를 통합했다.

## 4. 모바일 최종 동작

모바일에는 데스크톱 호버 규칙을 적용하지 않고 아래 규칙을 사용한다.

### 중앙 작품 선택과 컬러

- 기본적으로 모든 작품이 연한 흑백이다.
- 화면 중앙 영역의 작품 하나만 컬러로 표시한다. 작품이 여러 개 걸리면 중앙에 가까운 하나를 선택한다.
- 중앙 판정 범위를 넉넉하게 넓혔다. 현재는 화면 중앙에서 좌우 화면 너비의 25% 범위이며 경계 여유 10px를 적용한다.
- 해당 범위에 작품이 없으면 모두 흑백이 되고 정보는 퇴장한다.
- 데스크톱의 마우스 기반 X/Y 이동, Z축 기울기, 호버 확대는 없다. 작품 탐색을 위한 가로 스와이프 이동만 사용한다.

### 간격과 정보 위치

- 모바일 작품 간 간격을 이전 모바일 값의 3배로 늘렸다: `10.8vw → 32.4vw`.
- 제목과 년도는 **세로 방향으로 제목이 위, 년도가 아래**다. 모바일에는 `/` 구분자를 넣지 않는다.
- 정보 묶음은 선택된 작품 이미지의 실제 하단과 화면 하단 안전 영역 사이 빈 공간의 세로 중앙에 배치한다.
- 이미지 로딩이나 화면 크기 변경 시 위치를 다시 측정한다.
- 현재 제목은 `clamp(24px, 6vw, 40px)`, 년도는 20px이며 Pretendard를 사용한다. 긴 제목은 줄바꿈한다.

### 터치 스와이프와 관성

- 손가락을 왼쪽으로 밀면 다음 작품, 오른쪽으로 밀면 이전 작품으로 이동한다.
- 손가락이 닿아 있는 동안은 이동량을 1:1로 반영한다.
- 손을 놓은 뒤에는 최근 스와이프 속도에 비례한 관성이 이어진다. 빠르게 스와이프하면 여러 작품이 연속해서 지나가다가 서서히 감속한다.
- 관성 이동 중에도 중앙 작품의 색상과 제목·년도를 계속 갱신한다.
- 다시 터치하면 즉시 관성을 멈추고 새 터치를 따라온다. 반대 방향으로도 바로 조작할 수 있다.
- 잠시 멈췄다가 손을 놓거나 터치가 취소되면 관성을 이어가지 않는다. 다중 터치와 창 포커스 해제도 처리한다.
- 목록 양 끝에서 멈춘다. 작품별 스냅이나 무한 반복은 추가하지 않았다.

### 모바일 제목·년도 애니메이션 — 가장 최근 변경

- 모바일에도 글자별 등장·퇴장 애니메이션을 추가했다.
- 세로 배치를 유지하면서 제목 다음 년도 순서로 글자가 올라오고 선명해진다.
- 중앙 영역에서 벗어나면 현재 진행 지점부터 역방향으로 내려가며 사라진다.
- 이전 정보의 퇴장 중 새 작품이 중앙에 오면 이전 재생을 취소하고 새 작품 정보의 등장을 시작한다.
- 재생 속도는 데스크톱과 동일한 1.5배를 기본값으로 재사용한다.

| 모바일 관성 | 최대 4px/ms, 감쇠 시간상수 420ms, 최근 입력 유효시간 100ms |
| 모바일 판정 | 화면 너비 768px 이하 또는 hover:none 및 pointer:coarse |

모션 감소 설정에서는 글자 정보를 즉시 표시·제거하고 마우스 이동·기울기 및 모바일 관성을 적용하지 않는다.

## 7. 확인 결과와 남은 사항

- 최신 코드 변경 후 자동 테스트 26개 통과, 프로덕션 빌드 성공. 다른 기존 파일의 ESLint 경고와 Browserslist 데이터 경고는 남아 있다.
- 사용자는 실제 휴대폰에서 테스트 페이지를 열어 확인했으며 중앙 판정·간격·정보 위치 수정에 대해 긍정적으로 확인했다.
- 이후 추가한 관성의 체감 강도와 가장 최근 모바일 글자 애니메이션은 실제 기기에서 최종 확인이 필요하다. 자동 테스트 통과를 시각 검수 완료로 해석하지 않는다.
- 데스크톱의 80px 한 줄 제목이 아주 길 때 넘침 처리 방식은 후속 결정이다.
- 원근 회전 중 실제 브라우저의 호버 판정과 빠른 스와이프·화면 회전 동작도 시각적으로 확인할 수 있다.
- 메인 `/`에 반영하는 시점, 최종 배포, 최초 실루엣 인트로의 완전 삭제, 작품 무한 순환 등은 완료된 변경으로 간주하지 않는다.
- `CODEX_HANDOFF.md`에는 실루엣 처리나 초기 3점 테스트 요청 등 과거 문구가 일부 남아 있다. 이 문서의 현재 상태와 실제 코드를 함께 기준으로 삼고 구기획을 무조건 되살리지 않는다.

## 9. GPT에게 전달할 요청문

> 첨부한 인수인계 문서를 읽고 우리가 이전에 논의한 포트폴리오 Index 기획을 현재 상태로 갱신해 줘. 데스크톱은 전체 컬러 기본·호버 선택·전체 화면 XY 이동과 좌우 깊이 기울기, 모바일은 중앙 선택·넓은 간격·관성 스와이프·세로 제목/년도 애니메이션이 최종 방향이야. 여자 실루엣은 현재 코드상 최초 인트로에는 남아 있고 작품 탐색 중에는 사라져. 폐기된 비교안을 다시 최종안으로 취급하지 말고, 확정 요구와 조정 가능한 수치 및 미확정 사항을 구분해서 이후 기획 대화를 이어가 줘.
